# ShopController.Core

独立 .NET 8 核心库，无第三方依赖。只读写调用方指定的控制器配置，不读写 Chrome Cookie、密码或资料内容。Chrome 发现与启动由单独的 ChromeService 实现。

- `Validation.ValidateShop` 返回首个错误，`null` 表示通过。编辑记录时传 `excludeId`。空 `ProfileDirectory` 允许暂存，启动前须已绑定。
- 已知入口域名与平台标签须一致：`jd.com` / `jd.hk` 对应京东，`taobao.com` / `tmall.com` 对应淘宝或天猫，`pinduoduo.com` 对应拼多多；按域名本身或完整子域边界匹配，`Other` 同样执行该检查。未知专用域名保留可用。此规则只检查登记入口的明显错误，不阻止后续跨域跳转，不验证实际登录账号，也不代替 Chrome 资料隔离。
- 账号别名按去首尾空白、Unicode FormKC、忽略大小写归并。别名只是本地用户填写的身份标记，软件不据此确认实际登录账号。
- 自动分配隔离域为 JD / Alibaba（淘宝、天猫共享）/ Pdd / Other。每个域的不同账号使用不同资料；不同域可以复用资料。最低资料数为各域不同账号数量的最大值。
- `Plan` 不改动任何输入，只返回完整分配建议。资料不足或输入错误时 `CanApply=false`、`Assignments` 为空。只使用现有资料；用户须在 Chrome 自行创建新资料后刷新。
- 分配固定使用最低资料数。先用确定性偏好覆盖启发式选择资料池，再用最大权重匹配尽量保留绑定；不宣称跨所有资料池的全局最优保留率。调整已有绑定会给出警告，用户确认后整体应用。
- `ConfigStore` JSON 为 camelCase，平台使用枚举字符串（例如 `"JD"`）。仅接收明确的 `version: 1`，拒绝未知字段、重复字段、坏数据和账号绑定冲突。原子替换前校验旧文件；旧版本保留为 `<配置路径>.bak`。备份恢复由用户明确执行，不静默回退或覆盖坏配置。
- 同进程按配置路径串行；多 Native Messaging 进程的“读取－修改－保存”事务仍须调用方提供跨进程互斥锁。
- 持久配置或资料不代表后台登录永久有效；会话过期时在对应原生 Chrome 资料中重新登录。
